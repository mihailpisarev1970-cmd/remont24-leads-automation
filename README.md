# 🛠 Remont24 — Мультиканальная система сбора, AI-квалификации и маршрутизации лидов

Комплексный автоматизированный пайплайн на базе **n8n**, **Airtable** и **OpenAI (GPT-4o-mini via Polza AI)**, предназначенный для централизованного приёма входящих заявок на ремонт бытовой техники из разных каналов, их нормализации, дедупликации, интеллектуальной классификации и автоматической маршрутизации на ответственных мастеров.

## 🚀 Архитектура и каналы поступления данных

Сценарий объединяет три независимых источника трафика в единый стандартизированный поток:

1. **Telegram-бот (Реальный канал):** приём живых сообщений клиентов в реальном времени через ноду `Telegram Trigger` (бот `@rem_test24_bot`).
2. **Веб-сайт (Эмуляция):** приём веб-заявок в формате JSON через HTTP Webhook (`POST`).
3. **Авито (Эмуляция):** приём сообщений из чата сервиса в формате JSON через HTTP Webhook (`POST`).

## ⚙️ Логика работы пайплайна (Пошаговое описание)

1. **Приём входящих данных:**
   Заявка поступает в один из трёх входных триггеров (`Webhook_Site`, `Webhook_Avito` или `Telegram Trigger`).

2. **Единая нормализация (`Normalize Data`):**
   Вся входящая информация передаётся в JavaScript-ноду, которая приводит данные к единому контракту независимо от источника:
   * Извлекает `event_id`, источник (`source`), ID пользователя (`external_user_id` / `telegram_id`) и имя клиента.
   * Очищает и нормализует номер телефона до международного стандарта **E.164** (`+7XXXXXXXXXX`).
   * Извлекает чистый текст сообщения клиента и помещает его в поле `raw_messages`.

3. **Проверка на дубликаты и защита бюджета (`Search records` ➔ `Event Exists?`):**
   Перед отправкой данных в платную нейросеть выполняется поиск по полю `event_id` в таблице Airtable:
   * **Если событие найдено (Ветка `true` — Дубликат):** сценарий переходит к ноде `Mark Duplicate Event`. Статус существующей записи обновляется на `duplicate`, в поле `Notes` добавляется системный комментарий о повторном запросе. **Запрос к нейросети блокируется**, что защищает бюджет от лишних трат.
   * **Если событие новое (Ветка `false`):** заявка передается дальше по конвейеру на квалификацию.

4. **Интеллектуальная AI-квалификация (`Polza AI: Qualify Lead` + `Parse AI Result`):**
   Текст проблемы отправляется в модель `gpt-4o-mini` в строгом режиме генерации JSON (`json_object`). Нейросеть выполняет:
   * Определение типа техники (`service`): `refrigerators`, `ovens`, `washers` и т.д.
   * Оценку срочности ремонта (`urgency`): `urgent`, `high`, `medium`, `low`, `unknown`.
   * Формирование краткого содержания проблемы для мастера в поле `Notes`.

5. **Автоматическая маршрутизация мастеров (`responsible`):**
   На основе определённой категории система автоматически назначает ответственного специалиста:
   * ❄️ **Холодильники** (`refrigerators`) ➔ Мастер **Борис** (`boris`)
   * 🍳 **Духовки и плиты** (`ovens`) ➔ Мастер **Денис** (`denis`)
   * 🧺 **Стиральные машины и др.** (`washers`) ➔ Мастер **Анна** (`anna`)

6. **Фиксация в CRM (`Create Lead Record`):**
   Новая карточка лида со всеми классифицированными параметрами, нормализованными контактами и статусом `new` сохраняется в таблицу **Leads** базы Airtable.

## 📊 Структура полей в Airtable CRM

| Поле | Тип | Назначение |
| :--- | :--- | :--- |
| `event_id` | Single line text | Уникальный идентификатор события (ключ дедупликации) |
| `sources` | Single line text | Источник лида (`website`, `avito`, `telegram`) |
| `raw_messages` | Long text | Исходный текст обращения клиента |
| `service` | Single line text | Категория бытовой техники (`refrigerators`, `ovens`, `washers`) |
| `urgency` | Single line text | Приоритет/срочность (`urgent`, `medium`, `unknown`) |
| `status` | Single line text | Статус обработки (`new`, `duplicate`) |
| `responsible` | Single line text | Назначенный мастер (`boris`, `denis`, `anna`) |
| `Notes` | Long text | AI-выжимка проблемы / системные пометки |

## 📦 Инструкция по локальному развертыванию

1. **Импорт сценария:**
   Импортируйте файл `workflow.json` в свой инстанс **n8n**.
2. **Настройка Credentials:**
   * Добавьте токен Telegram-бота для ноды `Telegram Trigger`.
   * Подключите Personal Access Token для **Airtable**.
   * Укажите API-ключ для **Polza AI / OpenAI**.
3. **Активация сценария:**
   Переключите workflow в режим **Active** (Production).
4. **Тестирование:**
   * Для Telegram: отправьте текстовое сообщение боту [@rem_test24_bot](https://t.me/rem_test24_bot).
   * Для Сайта и Авито: импортируйте `postman_collection.json` в **Postman** и выполните тестовые POST-запросы.

Json для сайта
{
  "event_id": "site_evt_101",

  "page_url": "https://remont24.ru/refrigerators"

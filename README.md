## 🚀 Инструкция запуска с нуля

1. Склонируйте репозиторий или скачайте файлы проекта.

2. Для контейнерного/локального запуска скопируйте файл шаблона переменных окружения:

3. cp .env.example .env

## Импорт сценария в n8n

1. Откройте веб-интерфейс n8n.

2. В верхнем меню выберите Workflows - Import from File... и загрузите файл 01_Main_Ingestion.json

## Настройка учетных данных (Credentials в n8n)

1. Telegram Trigger: подключите Credentials вашего Telegram-бота, полученный через @BotFather.

2. Airtable Token API: создайте Personal Access Token (PAT) в Airtable с правами data.records:read и data.records:write для базы Ремонт24_CRM.  

3. Polza AI (Header Auth): укажите заголовок авторизации Authorization: Bearer <POLZA_API_KEY> в ноде HTTP Reques

## Активация и тестирование

1. Переключите тумблер workflow в верхнем правом углу в положение Published (Production-режим).

2. Импортируйте файл postman_collection.json в Postman и выполните готовые POST-запросы для эмуляции сайта и Авито.

## 🔒 Описание безопасности и архитектурных рисков


## Где хранятся данные:

1. Операционные данные лидов (имена, телефоны, текст проблем, категории, назначенные мастера) хранятся в защищенной облачной базе Airtable CRM (шифрование TLS/HTTPS при передаче и AES-256 в покое).

2. На сервере n8n сохраняются только временные технические логи выполнения сценариев (Executions).

Какие данные уходят внешним провайдерам:

В Polza AI / OpenAI API передаются исключительно три поля: name, phone_normalized и текст сообщения message для контекста квалификации. Вся база CRM, токены и системные ID во внешние LLM не передаются.

## Какие логи создаются:

1. В n8n: фиксируются Execution Logs (таймстемп вызова, статус HTTP-ответов, полезная нагрузка узлов и трассировка ошибок).  
2. В Airtable: фиксируются дата/время создания записи, статус обработки и история изменений в поле Notes.  

## Как удалить данные (152-ФЗ):

1. По запросу субъекта персональных данных запись безвозвратно удаляется из таблицы Leads в Airtable по идентификатору id или номеру phone_normalized.

2. Логи выполнения в n8n очищаются автоматически по настроенному TTL (параметр EXECUTIONS_DATA_PRUNE=true каждые 7 дней).
